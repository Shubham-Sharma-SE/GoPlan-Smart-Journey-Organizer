1. PROJECT OVERVIEW

Bharat Yatra is an interactive web-based travel management platform built 
specifically for Indian tourism. The platform enables tourists and travel 
planners to explore 22 iconic destinations across various Indian states, 
build multi-day itineraries, add multiple travellers, automatically compute 
discounted tourist entry ticket passes based on visitor age and gender, and 
interactively calculate a complete trip budget with real-time visual expense 
breakdowns.

Runtime requirement:
- Java Development Kit (JDK) 25 LTS or newer
- Compile with `javac --release 25` to keep generated bytecode aligned with the
  supported runtime

Technology Used:
- Frontend: HTML5, Modern CSS3 (Indian Tourism Theme: Forest Green, Subtle Saffron, 
  Navy Blue, Off-white), Interactive JavaScript (ES6+), HTML5 Canvas for charts
- Backend Server: Built-in Lightweight Java HTTP Server (com.sun.net.httpserver)
- Database: MySQL 8.0+ connected via JDBC (Java Database Connectivity)
- Models and Services: Core Java OOP Architecture (Java SE 25 LTS and higher)
- Zero external UI libraries or heavy node dependencies required


2. HOW TO RUN THE WEBSITE

There are two simple ways to launch and use the website:

METHOD 1: Instant Browser Launch (Zero Setup)
1. Navigate to the project directory:
   c:\codes\Travel_Planner(Java)\frontend
2. Double-click the file:
   index.html
3. The interactive website opens immediately in your default browser (Chrome, 
   Edge, Firefox, or Safari).
4. All interactive features (live search, state filters, ticket calculator, 
   trip planner, visual expense chart, and printable itineraries) are fully 
   functional.

METHOD 2: Running with Built-in Java Web Server and MySQL API
1. Open PowerShell or Command Prompt in the project root:
   cd "c:\codes\Travel_Planner(Java)"

2. Compile the Java source code:
   PowerShell users can run `.\backend\build-java25.ps1`, which compiles all
   sources with JDK 25 and runs the verification suite.

   For direct compilation:
   javac --release 25 -cp "backend\bin;backend\lib\*" -d backend\bin backend\src\bharatyatra\model\*.java backend\src\bharatyatra\database\*.java backend\src\bharatyatra\util\*.java backend\src\bharatyatra\dao\*.java backend\src\bharatyatra\service\*.java backend\src\bharatyatra\web\*.java backend\src\bharatyatra\main\*.java

3. Run the Java Web Server:
   java -cp "backend\bin;backend\lib\*" bharatyatra.web.WebServer

4. The server starts on port 8080 and automatically launches your web browser at:
   http://localhost:8080/index.html

5. It serves static web files and provides a live JSON REST API endpoint at:
   http://localhost:8080/api/destinations

METHOD 3: Launching via Main Entry Point
You can also launch the website entry point via:
   java -cp "backend\bin;backend\lib\*" bharatyatra.main.Main

4. HOW THE SYSTEM WORKS (ARCHITECTURE AND LOGIC)

The application combines modern web interactivity with clean software design:

1. Client-Side Reactive State (app.js):
   Maintains application state including active tab, current user session, 
   saved trips list, selected planner destinations, and dynamic travellers. 
   When any input or date changes, reactive render functions update the DOM 
   and recalculate formulas instantly without full page reloads.

2. Ticket Calculation Engine:
   Determines traveller age on the exact planned travel date:
   Age = Visit Year - DOB Year (adjusted for month and day).
   Applies configured business rules and calculates the individual payable fee.

3. Budget Aggregator:
   Total Estimated Budget = Entry Tickets + Accommodation + Transportation + Food.
   The Canvas engine translates these components into proportional angles on a 
   2D doughnut chart for visual clarity.

4. Data Persistence:
   All itineraries are synchronized to browser localStorage for immediate client-side 
   continuity. When paired with WebServer.java, it connects through JDBC to MySQL 
   using PreparedStatement for server-side persistence.


5. OBJECT-ORIENTED PRINCIPLES IMPLEMENTED

The project architecture strictly enforces object-oriented principles:

1. Encapsulation:
   All backend model classes (User, Destination, Trip, Traveller, Expense) use 
   private fields accessible only via public getters and setters with validation.

2. Abstraction:
   The abstract base class Ticket.java declares abstract contract methods:
   - public abstract double calculatePrice();
   - public abstract String getDiscountCategory();

3. Inheritance:
   Concrete classes inherit from Ticket:
   - ChildTicket extends Ticket
   - SeniorCitizenTicket extends Ticket
   - WomanTicket extends Ticket
   - GeneralTicket extends Ticket

4. Polymorphism:
   Each subclass overrides calculatePrice() to implement its category-specific 
   rate. At runtime, calling calculatePrice() executes the overridden subclass method.

5. Method Overloading:
   Implemented in Destination.java:
   - matches(String keyword)
   - matches(String state, String category)

6. Composition and Aggregation:
   - Trip contains a collection of Destinations.
   - Trip contains a collection of Travellers.
   - Trip contains an Expense object.
   - Itinerary aggregates a Trip.


6. DISCOUNT RULES AND CALCULATION LOGIC

Configured Project Discount Rules:

Category                     Discount Applied        Ticket Price Payable
--------------------------------------------------------------------------------
Children below 8 years       100% Discount (FREE)    Rs. 0.00
Women (aged 8 to 60)         50% Discount            50% of Base Price
Visitors strictly above 60   50% Discount            50% of Base Price
Other visitors (Adult men)   No Discount             100% of Base Price

Enforcement Rules:
- Age is calculated using Date of Birth relative to the planned visit date.
- Children below 8 receive free admission regardless of gender.
- Single discount rule: Only one discount applies per traveller (discounts never 
  compound; for example, a female senior citizen receives 50% discount, not 100%).
- Exactly 60 boundary: A visitor who is exactly 60 years old does not qualify 
  for the above-60 senior category (a 60-year-old male pays full price; a 60-year-old 
  female receives the 50% woman discount).


7. DATABASE SCHEMA AND RELATIONSHIPS

Database Name: bharat_yatra_db

Tables:
1. users: user_id (PK), full_name, email (UNIQUE), password_hash, dob, gender, 
   contact_number, created_at.
2. destinations: destination_id (PK), destination_name, state, city, category, 
   description, ticket_price, visiting_duration, created_at.
3. trips: trip_id (PK), user_id (FK), trip_name, start_date, return_date, 
   num_travellers, total_budget, created_at.
4. trip_destinations: trip_destination_id (PK), trip_id (FK), destination_id (FK).
5. travellers: traveller_id (PK), trip_id (FK), full_name, dob, gender, 
   ticket_price, discount_category.
6. expenses: expense_id (PK), trip_id (FK, UNIQUE), ticket_expense, 
   accommodation_expense, transport_expense, food_expense, total_expense.

Foreign keys specify ON DELETE CASCADE to ensure referential integrity.
